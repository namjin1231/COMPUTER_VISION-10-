## 1. 최종 모델: R-b (2차 실험)

| 항목 | 내용 |
|---|---|
| 이름 | R-b (2차 실험, `_r2`) |
| 모델 | TCNTE, 시드 0·1·2 세 개의 softmax 확률 평균. 미래 프레임은 보지 않음 |
| 파일 | `runs\Rb_r2_sel\tcnte_seed0\best.pt`, `seed1`, `seed2` (각 폴더의 config.json에 원래 에폭 기록) |
| 학습 데이터 | OmniFall 공식 train (OF-Syn + GMDCSA24 + CAUCAFall) + AI Hub 낙상 VS 새 학습 배우 18명 (C1~C4) |
| 학습 설정 | 처음부터 학습, `--seq-dir seq_r2 --hn-weight 3` (눕는 동작 가중치 3). AI Hub는 학습 조각의 13.1%. 나머지는 E2와 같음 (55특징, 가중 Focal Loss, lr 1e-3, 증강) |
| 에폭 | (OmniFall val macro F1 + AI Hub 새 val macro F1) / 2 최대 → 시드별 ep7 / ep33 / ep32 |
| 판정값 | smooth 3, th_fall 0.5, th_down 0.4, n_down 4, window_s 5초, v_gate 0.02 |
| 판정 규칙 | P(넘어짐) ≥ 0.5가 2프레임 연속이고 최근 16프레임 박스 아래쪽 속도 최대값 ≥ 0.02 → 의심. 5초 안에 P(쓰러짐) ≥ 0.4가 4프레임 연속 → 쓰러짐 확인. 확인이 `--alarm-s`초 이어지면 경보 |
| 실행 | `python demo_video.py --video 입력.mp4 --alarm-s 5` (기본값 = 최종). 설정 원본 `logs\demo_config.json` |

## 2. 데이터와 분할
- **OmniFall 공식 라벨·분할을 그대로 쓴다.**
  - OF-Syn은 학습 주력이다.
  - GMDCSA24·CAUCAFall은 학습, 검증, 시험(야간 포함)에 쓴다. 둘 다 사람 기준 분할이다. GMDCSA24는 train 1·3 / val 2 / test 4, CAUCAFall은 train 1~7 / val 10 / test 8·9.
  - OOPS는 시험 전용이다.
  - UR Fall·Le2i·CMDFall은 쓰지 않는다.
- **정답은 16클래스를 3클래스로 바꾼다** (`common.to3`).
  - 0 = 정상, 1 = 넘어지는 중, 2 = 쓰러져 있음.
  - `6 lying`은 −1로 학습과 채점에서 뺀다.
  - `5 lie_down`(눕는 동작)은 0이다.
- **AI Hub 낙상 VS 새 분할** (`labels\aihub_split_r2.csv`, `tools\r2_split.py`, seed 2026)
  - 배우 기준으로 학습 18명(225장면) / 검증 A·E·T(25장면) / 시험 D·F·G(34장면)로 나눴다.
  - 한 배우의 모든 장면과 카메라는 한 분할에만 있다. 쓰는 카메라는 CCTV 구도 C1~C4다.
  - 시험 3명에는 요양병원 장면이 없다(병원 22, 집 12).
  - 1차 분할 `labels\aihub_split.csv`(11/5/8명)는 그대로 남아 있다.
- **AI Hub 샘플 4장면** (00003_FY, 00015_SY, 00151_BY, 00047_N): 학습과 검증에는 쓰지 않는 시험 전용 데이터다.
- 평가 설명: 실제 촬영 데이터 3개(GMDCSA24, CAUCAFall, AI Hub)는 모두 사람 기준으로 나눠서, 학습에 쓰지 않은 사람으로 시험했다. AI Hub 샘플 4장면과 OOPS(유튜브)는 학습에 전혀 쓰지 않은 데이터다.

## 3. 지켜온 규칙
- **고르는 것은 val로만 한다.** 모델, 에폭, 판정값, 학습 옵션이 모두 해당한다. test는 최종을 정한 뒤 한 번만 돌리고, 숫자는 나온 그대로 쓴다.
- **선택 규칙은 결과를 보기 전에 정하고**, 시각과 함께 `logs\PROGRESS.md`의 '결정 기록'에 적는다.
- **기존 결과는 덮어쓰거나 지우지 않는다.** 새 결과에는 새 이름을 쓴다(_r2, _B, _v1, _preXX 백업).
- **코드 변경은 옵션으로 넣고, 기본 동작은 그대로 둔다.** 고친 내용은 `logs\changes.md`에 적는다.
- **2차 선택 규칙** (PROGRESS 결정 기록 '★ 2차 실험', 2026-11-17 22:27)
  - 판정값: 합친 val(OmniFall val 1253 + AI Hub 새 val 100)에서 spec95로 고른다. v_gate와 window_s 격자를 포함한다.
  - 조건: 특이도 ≥ 0.95, 눕기 영상 오경보율 ≤ 0.25, AI Hub val 비낙상 오경보율 ≤ v1(0.042).
  - 점수: (OmniFall val 민감도 + AI Hub val 민감도) / 2가 가장 높은 후보를 최종으로 한다.

## 4. 실험 목록 (채택 / 기각과 이유)
| 실험 | 내용 | 결과 |
|---|---|---|
| E1 | GRU로 파이프라인 끝까지 한 번 | 확인용 (val macro 0.737) |
| E2 | TCNTE / GRU / 1D-CNN × 시드 3 | TCNTE 3개 앙상블을 메인으로 채택 (= v1) |
| E3 | 레퍼런스 방식 (넘어지는 순간 2클래스, 1초 창) | 비교용 (final_tables 2절, 넘어지는 순간 탐지끼리 비교) |
| E4 | TCNTE 증강 없음 | 증강 있음(E2)이 대부분 조금 나음 → 증강 유지 |
| (E5) | 번호 없음 (진행한 실험 없음) | – |
| E6 | OOPS train/val을 학습에 섞기 | OmniFall test 확인 민감도 0.608 → 0.599로 이득 없음 → 최종 설정 안 바꿈 |
| 평가 개선 C | 시드 3개 앙상블 + smooth 3 + spec95 | 채택 (v1 설정) |
| YOLO s960 | 더 큰 포즈 모델 | val 지표가 엇갈림 → 기각 |
| cosine lr, X_wide, X_g2, 5개 앙상블 | 작은 개선 후보 | 모두 기준 미달 → 기각 |
| B 후보: X_bnd (경계 무시), X_hn (눕기 가중치 3), 혼합 앙상블 | 1차 B 단계 | X_hn을 '1차 최종(B 최종)'으로 채택 (v_gate 0.02, 4초, 0.4/0.4/4) |
| E7 | OmniFall + AI Hub 1차 분할 학습 (AI Hub 25%) | 1차 규칙 (OmniFall val 하락 ≤ 0.005)에서 기각 |
| E8a / E8b | X_hn에서 이어서 / 처음부터, AI Hub 약 12% | 1차 규칙에서 둘 다 기각 |
| 2차 v1, X_hn, X_bnd | OmniFall만 학습, 재학습 없이 2차 규칙으로 다시 평가 | 점수 0.530 / 0.506 / 0.506 → 최종 아님 |
| 2차 R-a | X_hn에서 이어서, AI Hub 새 분할 13%, lr 1e-4, 10에폭 | 점수 0.695 → 기각 (OmniFall val 민감도 0.509로 낮음) |
| **2차 R-b** | 처음부터, AI Hub 새 분할 13% | **점수 0.730 → 최종** |
| 2차 R-c | 처음부터, AI Hub 새 분할 23% | 점수 0.669 → 기각 (OmniFall val 민감도 0.457로 낮음) |

- 1차에서 2차로 넘어간 이유: 1차 규칙은 OmniFall 성능을 지키는 쪽이어서 AI Hub를 더한 모델이 모두 탈락했다. 사용자가 프로젝트 목표(요양시설을 포함한 실내 CCTV)에 맞게 선택 규칙과 AI Hub 분할을 다시 정하고, v1에서 출발해 다시 골랐다.

## 6. 알려진 한계와 다음에 할 일
- **알려진 한계**
  - **침대에 스스로 눕기**: OmniFall test에서 눕는 동작이 있는 정상 영상의 14.2%에 경보가 났다. 침대 영역 예외 처리는 없다. `limit_bed.mp4`가 그 사례다.
  - **넘어진 뒤 눕지 않는 자세**: 앉거나 웅크리고 있으면 '쓰러짐 지속'이 확인되지 않아 놓칠 수 있다.
  - **AI Hub 밖의 실제 촬영 오경보 증가**: CAUCAFall 일상 9개 중 2개, GMDCSA24 조명 끔 정상 11개 중 3개에서 경보가 났다(v1은 0개, 1개). 정면·낮은 시점 카메라라면 확인이 필요하다.
  - **AI Hub 시험 규모**: 시험 배우가 3명이고 요양병원 장면이 없다.
- **다음에 할 일**
  1. 현장 맞춤 학습: 설치할 요양시설 카메라 영상을 모아 val과 test로 쓰고, 필요하면 학습에도 더한다. 판정값(특히 window_s, th_fall)도 그 val로 다시 고른다.
  2. 침대 눕기 오경보: 침대 영역 지정, 또는 눕기 영상을 더 모아 가중치를 다시 학습한다.
  3. 넘어진 뒤 앉아 있거나 웅크린 자세의 정답 규칙을 정하고 데이터를 확보한다.
  4. 외부 검증: Le2i, MCFD 같이 학습에 쓰지 않은 공개 데이터로 test만 해 본다. 이 프로젝트에서는 일부러 쓰지 않았으므로 깨끗한 외부 검증이 된다.
